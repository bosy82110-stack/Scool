# تصميم واجهة WiFi Guardian

## الرؤية

WiFi Guardian هو تطبيق Android منزلي لإدارة شبكة ZTE ZXHN H168N من مكان واحد. يركز التصميم على الاستخدام بيد واحدة، والوضوح السريع، وعدم الإيحاء بأن وظيفة غير مدعومة من إصدار الراوتر تعمل فعليًا. الواجهة تعتمد نمطًا قريبًا من تطبيقات iOS وAndroid الحديثة: شريط علوي بسيط، بطاقات واضحة، أزرار كبيرة، حالات اتصال مفهومة، وتأكيد قبل الإجراءات المؤثرة.

## قائمة الشاشات

| الشاشة | المحتوى والوظيفة الأساسية |
|---|---|
| لوحة الشبكة | حالة الشبكة، اسم الراوتر، عدد الأجهزة المتصلة، عدد الطلبات المعلقة، وزر تحديث واضح. |
| الأجهزة المتصلة | قائمة FlatList للأجهزة مع اسم مخصص، نوع تقريبي، IP، MAC، حالة السماح، وسرعة/أولوية الاتصال إن كانت متاحة. |
| تفاصيل الجهاز | اسم الجهاز، عنوان IP وMAC، آخر ظهور، حالة الوصول، أزرار السماح والحظر، وإعداد أولوية السرعة. |
| طلبات الاتصال | أجهزة جديدة في حالة «بانتظار الموافقة» مع زري قبول ورفض، وشرح أن الموافقة تعتمد على إعدادات الراوتر. |
| إعدادات الراوتر | عنوان الراوتر المحلي، حالة الاتصال، طريقة الإدارة، اختبار الاتصال، وحقول دخول تُحفظ محليًا بشكل آمن عند الحاجة. |
| إعدادات التطبيق | قفل التطبيق بالبصمة، الوضع الداكن، أسماء الأجهزة المحفوظة، وإعادة ضبط البيانات المحلية. |
| شاشة الحالة/الخطأ | رسائل عملية عند عدم الاتصال بالراوتر أو عدم دعم ميزة مثل حد السرعة الفردي، مع خطوات تصحيحية. |

## التخطيط المرئي

يستخدم التطبيق اتجاهًا رأسيًا 9:16. في أعلى لوحة الشبكة يظهر عنوان «شبكتي» مع مؤشر أخضر أو كهرماني لحالة الاتصال، ثم بطاقة ملخص تحتوي على عدد الأجهزة المتصلة وزر «فحص الآن». أسفلها تظهر بطاقة الطلبات المعلقة، ثم قائمة مختصرة بآخر الأجهزة النشطة. شريط التنقل السفلي يتكون من «الرئيسية»، «الأجهزة»، و«الإعدادات»؛ أما تفاصيل الجهاز وطلبات الاتصال فتفتح كشاشات داخلية أو أوراق سفلية لتقليل حركة اليد.

كل عنصر جهاز عبارة عن بطاقة بارتفاع مريح للمس، تحتوي على أيقونة نوع الجهاز، اسم الجهاز، وصف قصير بعنوان MAC، وشارة حالة. الضغط على البطاقة يفتح التفاصيل، بينما إجراءات القبول أو الحظر تكون أزرارًا صريحة ولا تعتمد على السحب فقط. قبل الحظر أو إعادة ضبط الإعدادات يظهر تأكيد يذكر اسم الجهاز.

## التدفقات الرئيسية

### الاتصال الأول

يفتح المستخدم التطبيق، يختار «إضافة راوتر»، يكتب عنوان الإدارة المحلي، ثم يضغط «اختبار الاتصال». بعد نجاح الاختبار تظهر حالة الراوتر والميزات المكتشفة. إذا كانت بيانات الدخول مطلوبة، يكتبها المستخدم داخل التطبيق وتُحفظ في التخزين الآمن على الجهاز فقط.

### مراجعة جهاز جديد

يظهر الجهاز الجديد في «طلبات الاتصال» بحالة معلقة. يفتح المستخدم التفاصيل للتأكد من MAC وIP، ثم يضغط «السماح» أو «رفض». يعرض التطبيق نتيجة العملية، وإذا لم يدعم الراوتر التحكم المطلوب يوضح ذلك بدل عرض نجاح وهمي.

### التحكم في الجهاز

من قائمة الأجهزة يضغط المستخدم على جهاز، ثم يغير الاسم المحلي أو يختار «حظر». عند توفر QoS أو قاعدة أولوية في إصدار الراوتر، يظهر إعداد السرعة/الأولوية؛ وعند عدم توفر حد سرعة صارم، يظهر تنبيه بأن المتاح هو أولوية مرور فقط أو أن الوظيفة غير مدعومة.

### تأمين التطبيق

من الإعدادات يفعّل المستخدم قفل البصمة. عند فتح التطبيق لاحقًا تظهر شاشة فتح قصيرة قبل عرض الأجهزة أو تنفيذ أوامر الإدارة. بيانات الراوتر الحساسة لا تظهر في السجل أو الرسائل.

## الألوان والعلامة

| الاستخدام | اللون | الدلالة |
|---|---|---|
| اللون الأساسي | `#165DFF` | إجراء رئيسي واتصال موثوق |
| الخلفية | `#F6F8FC` | مساحة هادئة للوحة التحكم |
| السطح | `#FFFFFF` | بطاقات وقوائم |
| النص الأساسي | `#10233F` | وضوح وتباين مرتفع |
| النص الثانوي | `#61708A` | معلومات مساعدة |
| نجاح/مسموح | `#168A5B` | جهاز مسموح أو اتصال ناجح |
| انتظار | `#C87900` | طلب يحتاج قرارًا |
| حظر/خطأ | `#C83E4D` | جهاز محظور أو فشل عملية |
| حدود | `#DDE4EF` | فصل هادئ بين العناصر |

يُستخدم اللون الأساسي باعتدال في زر واحد رئيسي داخل كل سياق. الحالات لا تعتمد على اللون وحده، بل تجمع بين اللون والنص والأيقونة، دعمًا لإمكانية الوصول.

## مبادئ تقنية وتجريبية

ستُحفظ أسماء الأجهزة والإعدادات المحلية باستخدام AsyncStorage، بينما تُحفظ بيانات الدخول الحساسة باستخدام SecureStore. ستستخدم القوائم FlatList، وستلتزم الشاشات بـ ScreenContainer، مع حالات تحميل وفشل وفراغ حقيقية. النسخة الأولى ستفصل بين طبقة واجهة الراوتر وطبقة واجهة التطبيق حتى يمكن تبديل طريقة التكامل بعد معرفة إصدار firmware الفعلي.
